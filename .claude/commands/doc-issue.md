# 문제 해결 문서화 파이프라인

당신은 방금 문제를 해결했습니다. 이 문제가 다시 발생하지 않도록 체계적으로 문서화해주세요.

## 📝 문서화 프로세스

다음 질문들에 답변하면서 문제를 분석하고 문서화합니다:

### 1. 문제 파악
- **어떤 증상이 발생했나요?** (사용자가 본 에러, UI 깨짐 등)
- **언제 발생했나요?** (특정 작업 중, 특정 조건에서)
- **어떤 파일/컴포넌트에서 발생했나요?**

### 2. 원인 분석
- **근본 원인(Root Cause)은 무엇인가요?**
- **왜 이런 문제가 발생했나요?** (설정 이슈, 코드 로직, 환경 문제 등)
- **이 문제가 발생한 구조적/기술적 배경은?**

### 3. 해결 방법
- **어떻게 해결했나요?** (구체적인 코드 변경, 설정 수정)
- **다른 해결 방법은 없었나요?** (시도한 방법, 장단점 비교)
- **최종적으로 선택한 방법과 이유는?**

### 4. 재발 방지
- **같은 문제가 다시 발생할 수 있나요?** (가능성 평가)
- **어떤 상황에서 재발할 수 있나요?**
- **재발을 방지하려면 무엇을 체크해야 하나요?** (체크리스트)

### 5. 프로젝트 영향도
- **발생 빈도**: 낮음/중간/높음
- **영향도**: 낮음/중간/높음 (사용자 경험, 개발 생산성)
- **긴급도**: 낮음/중간/높음

## 📂 문서 저장 위치

`.claude/agents/` 디렉토리에 다음 형식으로 저장합니다:

**파일명 규칙**: `[카테고리]-[문제요약].md`

**카테고리 예시**:
- `css-` : CSS/스타일링 관련 (예: `css-tailwind-not-working.md`)
- `api-` : API/백엔드 통신 (예: `api-cors-error.md`)
- `build-` : 빌드/배포 관련 (예: `build-vite-error.md`)
- `state-` : 상태관리 관련 (예: `state-context-update.md`)
- `performance-` : 성능 이슈 (예: `performance-rerender.md`)
- `component-` : 컴포넌트 로직 (예: `component-modal-unmount.md`)
- `routing-` : 라우팅 관련 (예: `routing-404-handling.md`)
- `data-` : 데이터 처리 (예: `data-validation-error.md`)

## 💡 작성 가이드라인

### DO ✅
- **구체적인 코드 예시** 포함 (Before/After)
- **재현 가능한 단계** 명확히 작성
- **대안 방법들**과 각각의 장단점 비교
- **실제 프로젝트 설정** 정보 포함 (버전, 설정 파일)
- **체크리스트** 형태로 실행 가능한 항목 작성
- **검색 가능한 키워드** 포함 (에러 메시지, 클래스명 등)

### DON'T ❌
- 모호한 설명 ("잘 안 되었어요" → ❌)
- 해결 방법만 나열 (원인 분석 누락)
- 프로젝트별 차이 무시 (버전, 환경 정보 누락)
- 일회성 해결책 (재발 방지 전략 없음)

## 🎯 문서화 목표

1. **빠른 검색**: 키워드로 즉시 찾을 수 있도록
2. **완전한 이해**: 왜 발생했는지 기술적 배경 포함
3. **즉시 적용**: 코드 복사-붙여넣기로 해결 가능
4. **예방 중심**: 재발 방지가 핵심 목표
